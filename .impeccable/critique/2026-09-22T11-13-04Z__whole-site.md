## Design Specificity Verdict

**LLM assessment:** Split cleanly along a content/chrome line. The actual tools are genuinely authored for this lab — the CSV parsers auto-detect Moku-style `%`-prefixed metadata, the FITS plotter runs a custom parser against real committed lab data with instrument-panel chrome (green-phosphor crosshair, colorbar, mono readouts), and the calculators use this lab's real units and framing. That's not reskinned Bootstrap.

But the presentation undercuts it at the front door: the homepage (`src/app/page.tsx`) is a two-line placeholder — "Welcome! QUOP is short for quantum optics. Have fun!" — with no links and none of DESIGN.md's documented 2×2 hero grid. And the flagship "physicist's notebook" palette DESIGN.md describes in detail (warm parchment, sepia borders, midnight-slate) doesn't exist in the shipped CSS at all — only the oxblood/amber ink-accent pair is real. The tools are specific; the shell around them currently isn't, and the notebook identity is aspirational documentation, not a built reality.

**Deterministic scan:** 106 detector findings, all `advisory`/`quality` severity (design-system-color: 48, design-system-radius: 35, design-system-font-size: 23), concentrated in `globals.css` (97) plus `chart-series-palette.ts` (4), `builder/types.ts` (3), `scene-theme.ts` (2). Cross-checking against DESIGN.md's sidecar shows most of these are false positives — the detector doesn't normalize `rgb(r g b / a)` vs `rgba()` syntax or recognize alpha variants of a documented base color (e.g. the green-phosphor `#9cff8f`/`#b9ffb3` FITS readout colors, the `0.65rem`/`0.9rem`/`1rem` radii the sidecar documents verbatim). Genuine drift remains, though: a wholly undocumented 4-color chart-series palette (`#1f6f78`, `#d17a22`, `#4a6d3b`, `#5c4b8a` in `chart-series-palette.ts`), the in-progress 3D builder's colors (`scene-theme.ts`, `builder/types.ts`) which post-date DESIGN.md entirely, and a scatter of one-off radius/font-size values in `globals.css` with no documented counterpart at all.

**Visual overlays:** Not available — no browser automation tool exists in this environment, so both assessments worked from source code rather than a live rendered page. Treat layout/contrast findings as inferred from CSS, not confirmed on-screen.

## Overall Impression

The engineering is more mature than the front door. Underneath, this is a well-built, genuinely lab-specific toolkit with a distinctive signature feature (the FITS instrument readout). But a first-time visitor's actual entry point — the homepage — does none of the wayfinding work the rest of the site earns, and the documented design system has drifted from the shipped code in both directions (things documented but never built, and things built but never documented).

## What's Working

1. **CSV parsing (`csv-plotter.tsx`/`generic-csv-plotter.tsx`)** — auto-detects comment markers, finds the header row by column-count matching rather than assuming row 1, reports skipped-row counts, and surfaces non-plotted metadata separately. Real "tuned to this lab's instruments" work.
2. **FITS/scatter-chart instrument readout (`fits-image-viewer.tsx`, `interactive-scatter-chart.tsx`)** — the green-phosphor crosshair, live colorbar, slice extraction with CSV export, and full-control PNG export match DESIGN.md's "instrument console" half exactly, and this is more capable than most bespoke internal lab tools.
3. **Builder's undo/redo + autosave resilience (`use-builder-scene.ts`)** — clean checkpoint/preview reducer, wrapped in try/catch on both localStorage read and write, so a corrupt autosave or private-browsing quota error degrades gracefully instead of breaking the page.

## Priority Issues

**[P0] Homepage is a functionless placeholder**
Why it matters: `src/app/page.tsx` renders only "Welcome! QUOP is short for quantum optics. Have fun!" with zero links and none of DESIGN.md's documented four-tile hero. This is the single highest-traffic surface on the site and it does zero wayfinding for an outside visitor with no lab context — directly undercutting PRODUCT.md's stated purpose of representing the group to visitors.
Fix: Build the 2×2 hero grid (Calculators/Theory/Plotters/Experiment tiles, each with its wayfinding-color top stripe) that DESIGN.md already specifies.
Suggested command: /impeccable shape (to plan it), then /impeccable polish

**[P1] Nav dropdown flyouts are keyboard-inaccessible**
Why it matters: The `NavItem` flyout relies on `group-hover:opacity-100 group-hover:pointer-events-auto` with no `focus-within` equivalent. A keyboard-only user tabbing through "Plotters"/"Calculators" can't see sublinks appear and may tab into invisible, `pointer-events: none` links — a WCAG 2.1.1/2.4.7-class failure.
Fix: Add `focus-within:opacity-100 focus-within:pointer-events-auto` alongside the existing hover classes.
Suggested command: /impeccable audit

**[P1] Calculator errors never say why**
Why it matters: Every calculator collapses empty/non-numeric/negative/zero input into one "Invalid input." message, giving no path to correction.
Fix: Differentiate causes ("Enter a positive wavelength" vs. "Couldn't read that number").
Suggested command: /impeccable clarify

**[P2] Design system documentation and implementation have drifted apart in both directions**
Why it matters: DESIGN.md documents a warm-parchment/sepia palette that was never shipped, while the code independently introduced a 4-color chart-series palette (`chart-series-palette.ts`) and the builder's own colors (`scene-theme.ts`, `builder/types.ts`) that DESIGN.md never mentions. Left alone, the doc stops being reliable authority for future design work in either direction.
Fix: Either implement the documented parchment palette or correct DESIGN.md to match reality; separately, document the chart-series and builder-3D color systems (or fold them into the existing token set).
Suggested command: /impeccable document

**[P2] Plotters section exceeds the cognitive-load guideline with under-differentiated names**
Why it matters: 5 plotter variants are shown at once in both the nav flyout and the `/plotters` index — over the ≤4-item guideline — and names like "CSV Plotter" vs. "Time CSV Plotter" don't communicate the actual distinguishing constraint (a required `time` column) until you're inside the tool.
Fix: Group or rename for self-differentiation, or move one variant behind progressive disclosure.
Suggested command: /impeccable layout

## Minor Observations

- `src/app/energy-wavelength-calculator/page.tsx` and `src/app/lidt/page.tsx` are clean `redirect()` stubs, not orphaned cruft — no action needed.
- `TransitionProvider`/`NavTransitionLink`/`WavefunctionBanner`/`orbitalPhase` are confirmed genuinely unreferenced — DESIGN.md's dead-code claim checks out.
- `globals.css` has duplicated rule blocks (`.fitsImageViewport`, `.fitsColorbar` defined 2-3x) — a maintainability smell, not user-visible.
- A scatter of one-off radius/font-size values in `globals.css` (e.g. 0.35rem, 0.72rem, 0.2rem, 0.92rem, 1.05rem) fall outside even the documented radius/font scale — minor, genuine drift.
- Detector's "exit 0 = clean" convention doesn't hold in practice: this run had 106 advisory findings but still exited 0 (only blocking-severity would exit 2) — worth knowing so a clean exit code isn't mistaken for zero findings.
